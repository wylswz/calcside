# AGENTS.md

## Commands
- API benchmark: `make benchmark` runs `benchmark/api.js` with k6 against an already-running dedicated server; `make benchmark-smoke` checks exec/lifecycle/read with one VU and one iteration each. Configure `CALCSIDE_BASE_URL`, optional `CALCSIDE_API_KEY`, and `BENCH_*` variables (see README); do not use k6 CLI VU/iteration overrides or distributed execution. Instances are cleaned up, but execution/audit/instance history remains in the database.
- Release gate: build `ghcr.io/wylswz/calcside:test` + `calcside-migrate:test` first; `python3 benchmark/deploy-release.py kind|compose STATE_DIR` deploys an isolated stack — a fresh kind cluster (`TEST_KIND_CLUSTER`, port-forward on `TEST_KIND_PORT` 18080) or the standalone `docker/compose.test.yml` project (`TEST_COMPOSE_PROJECT`) — writes credentials plus `STATE_DIR/connection.json` (`base_url`/`api_key`, the primary interface; `test.env` mirrors it), and never reuses an existing cluster/project or prints secrets. `python3 benchmark/run-release.py kind|compose OUT_DIR --state STATE_DIR` runs 3 integration + 3 timed k6 cases and renders `report.md`; `deploy-release.py ... diagnostics OUT_DIR` collects sanitized status/logs (never Secrets, helm values, or credentials). A release verifies both backends before publishing. CI runs both backends in the `deployment` job of `.github/workflows/deployment-tests.yml`.
- Go checks: `go build ./... && go vet ./... && gofmt -l . && go test -race ./...`
- Web checks: `pnpm -C web typecheck && pnpm -C web lint && pnpm -C web build`
- Editor completion tests: `pnpm -C web test` (Node >= 22.18, built-in test runner and TypeScript stripping; no browser needed).
- Helm chart: `charts/calcside`; `make helm-lint` lints and renders the SQLite, PostgreSQL, and ingress variants and rejects disabled or zero workers. `charts/deploy-test.py` (repo tooling, not packaged) is a one-command test deploy: it generates all secrets at run time, applies a disposable in-cluster PostgreSQL sharing the generated password, and runs `helm upgrade --install`; `--uninstall` tears it down, `--values-only` only emits the values file, `--no-postgres` targets an existing database via `TEST_PG_*`. CI's `helm` job runs it. Pushing a `v*` tag runs `.github/workflows/release.yml`, which publishes the multi-arch API/worker and migration images plus the OCI chart to GHCR and creates the GitHub release. The migration image (`docker/Dockerfile.migrate`) bundles both Atlas dialect directories for the chart's init container.
- `make gen` regenerates OpenAPI and Wire code; `make gen-check` fails if generated files drift. `make wire` regenerates the API, worker, and shared-node injectors; `make wire-check` checks them without modifying files and runs in Go CI.
- `make lint` runs gen-check + vet + gofmt + web typecheck/lint; `make build` builds web then `bin/calcside`, `bin/calcside-worker`.
- `make dev`/`serve-dev` pass `--net-allow-cidrs=$(DEV_NET_ALLOW_CIDRS)` (default `198.18.0.0/15`) to exempt fake-ip proxy ranges from net's SSRF blocking; set `DEV_NET_ALLOW_CIDRS=` to disable.
- Dev: `make dev` starts the API in dev mode (anonymous auth, no login) on :8787, a separate worker, and Vite on :5173. `make serve-dev` starts the same API/worker pair with the embedded UI instead of Vite. The only public address settings are `CALCSIDE_CONSOLE_ORIGIN` (shared by UI, OAuth callbacks and preview CSP) and `CALCSIDE_ARTIFACT_PREVIEW_BASE_URL`; the old base-url/artifact-console-origin settings are removed. Dev recipes set the console origin to the actual UI address unless explicitly overridden.
- `make test-cgroup` runs the per-instance cgroup memory-limit test (`internal/node/subproc/cgroup_linux_test.go`) as root in a privileged throwaway Docker container; plain `go test` skips it unless `CALCSIDE_TEST_CGROUP=1`. `make test-cgroup-host` runs it on a Linux host via sudo with `-race`.
- CI (`.github/workflows/ci.yml`): `unit` (Go build/vet/gofmt/`test -race`), `integration-postgres` (`make test-postgres`), `integration-cgroup` (`make test-cgroup-host` + `make test-cgroup`), `integration-sdk` (`make sdk-test`). Actions are pinned by commit SHA.
- Python SDK (`sdk/python`, uv project): `make sdk-test` (pytest, builds + boots a dev-mode server), `make sdk-lint` (ruff). Not part of `make test`/`make lint`.

## Conventions
- Dependency assembly uses Google Wire v0.7.0 (pinned as a Go tool) in `cmd/calcside`, `cmd/calcside-worker`, and `internal/node`. Edit `wire.go` / providers, then run `make wire`; never hand-edit `wire_gen.go`. Keep Wire out of domain services and preserve provider cleanup order (audit flush before store close). Normal builds use committed generated Go, with no runtime Wire dependency.
- No container / host process capabilities. New capabilities implement `capability.Factory` and must route every op through `Gate.Invoke` so hooks and audit see it.
- Result/Call metadata passed to hooks must be JSON-able and must never contain file contents or response bodies.
- Gin strict adapters must pass `Request.Context()` to services/runtimes, never the pooled `*gin.Context`; transport cleanup can outlive the handler and race with Gin context reuse (API `realCtx`, worker `requestContext`).
- User Rego policies run with a restricted capability set (see `internal/policy`); keep dangerous builtins out.
- Policies are per instance: `--policy-dir` server policies always apply; user library policies (unique `(workspace_id, name)`) apply only when named in `spec.policies`, resolved and snapshotted by `service/sandbox` at create (`PolicyBundle.User` is keyed by name). There is no `enabled` flag. Built-in policy descriptors live in `internal/runtime/policies.go`; `builtin.block_private_network` is opt-in (not default-selected) and enforced by net at dial time (all DNS results checked before dialing). Omitted/null `spec.policies` selects defaults; an explicit list replaces them. Preserve `[]` through serialization (no `omitempty`), including API/worker/subprocess boundaries. Built-ins share the policy catalog with Rego, reserve `builtin.`, and are read-only. The old `--net-allow-private` flag is removed; `--net-allow-cidrs` remains an exemption for the selected built-in policy.
- Authorization is decided only in `cmd/calcside/internal/service/access` (roles ∩ key ceiling ∩ shares; invisible → not_found, then forbidden); services never compare user IDs and `TestRouteCoverage` fails if a generated operation lacks an access table entry. Bound API keys store one prefixed resource id in `api_keys.bound_id` (`ins_…` instance, `app_…` application); access hides everything except that resource, and the resource's death revokes them (`RevokeBoundKeys`). The API keeps `instance_id`/`application_id` fields, mapped by prefix in `api/dto`. New bindable resources reuse `bound_id` — do not add per-resource key columns.
- Store changes: update the interface, the GORM impl (`cmd/calcside/internal/gormstore`), and `internal/store/storetest` conformance suite.
- Store backends: `--store sqlite|postgres` (`gormstore`, one impl for both); keep store queries dialect neutral.
- Schema migrations: hand-written Atlas SQL in `cmd/calcside/internal/gormstore/migrations/{sqlite,postgres}`; matching filenames/versions are checked by `TestMigrationDirsInLockstep`. `make migrate-new name=<desc>` creates both files; edit SQL, keep row structs in sync, then `make migrate-hash`. Never edit applied files. No AutoMigrate, schema generation, embedded execution, or Atlas Go dependency. The application only opens the DB; run `ATLAS_DB_URL=... make migrate-apply MIGRATION_ENV=sqlite|postgres` before serving (PostgreSQL URLs should set `search_path=public`). `make migrate-status` uses the same variables. Atlas owns history, locks, transactions, and checksum checks.
- Migration history was consolidated pre-release: `cmd/calcside/internal/gormstore/migrations/{sqlite,postgres}/20261024133846_baseline.sql` is the only migration per dialect, including the final `llm_providers` shape (`source`/`sum`/`models`, no `type` column). Fresh empty databases apply it normally; existing pre-consolidation dev DBs are not upgraded — reset them intentionally, never auto-baseline an arbitrary nonempty DB. Never edit applied migration files going forward. `TestBaselineLLMProviders` applies the baseline alone from a scratch dir and asserts the consolidated schema.
- Atlas CLI 1.2.2 is pinned in CI (download checksum verified) and Compose (image digest). Install it locally for Go/SDK DB tests and `make dev`/`serve-dev`; these commands migrate before use. Compose runs a separate `migrate` service before the API. Production binaries require no Atlas executable.
- `make test-postgres` runs store conformance/migration tests against throwaway Docker PostgreSQL; direct tests can use `CALCSIDE_TEST_POSTGRES_DSN` (admin URL with CREATE DATABASE permission). Plain `go test` skips PostgreSQL integration but still checks both directories' checksums. `make migrate-validate` checks both directories' checksums without a dev database; migration replay is covered by SQLite tests and `make test-postgres`.
- API changes: edit `api/openapi.yaml` first, then `make gen`; never hand-edit generated files (`cmd/calcside/internal/api/gen`, `web/src/api/schema.ts`).
- Worker protocol changes: edit `api/worker.openapi.yaml`, then `make gen`. Worker-served ops generate into `internal/runtime/remote/gen`; `api-callback`-tagged ops (worker→API reverse calls, e.g. ext tree resolution) generate the API-side strict server into `cmd/calcside/internal/api/intgen` and the worker's client into `cmd/calcside-worker/internal/apiclient`. Request/response bodies map via `x-go-type` onto `internal/runtime` contract types — payloads change in the contract package, not the spec.
- Extensions (`ext` capability): Starlark-only (never native binaries); they compose base capabilities and every op must route through `Gate.Invoke` (nested base-cap calls inherit allowlists, secrets, hooks, audit). Remote sources require an explicit `@version` and an `h1:` sum; git CLI is required at runtime for fetches. Server opt-in flags: `--ext-allow-sources` / `--ext-local-roots` / `--ext-cache-dir`. Local sources use `{root-name}/{extension}` (e.g. `contrib/tavily`), where root-name is the configured root directory basename; catalog, specs, and worker callbacks never use absolute host paths. Absolute/traversal sources and ambiguous matches across roots are rejected.
- The API tier never executes code: every instance call forwards to `calcside-worker` processes over the signed remote protocol (`--workers` + `--worker-key` are required on the API, `--api-addr` + `--shared-key` on the worker). Each instance runs in its own OS process under the worker's `internal/node/subproc.Supervisor`, which re-executes the worker binary as `<bin> __instance` (config JSON on stdin, never argv/env) and forwards the worker protocol over a per-child unix socket via `remote.Direct`. Globals/VFS live in the child's memory — Starlark values (functions, bindings) are not serializable, so don't add globals snapshots. A child exits when its stdin closes. Subproc tests re-exec the test binary from `TestMain`. Design: `docs/execution-routing.md`. `--instance-memory-max` puts each child in its own cgroup v2 group (`internal/node/subproc/cgroup_linux.go`); without usable cgroup v2 it warns and runs uncapped.
- Docker: the compose worker starts as root via `docker/worker-entrypoint.sh` (needs `security_opt: writable-cgroups=true`, Docker Engine >= 28, for a rw `/sys/fs/cgroup`), delegates `/calcside` to the `calcside` user, then `su-exec`s down. `.dockerignore` excludes `docker/` except that script.
- Pin dependency versions published at least 7 days ago.
- `web/dist/README.txt` is a committed placeholder so Go builds work without Node.

- The console administrator uses bootstrap-only `CALCSIDE_ADMIN_USERNAME` / `CALCSIDE_ADMIN_PASSWORD`, without `--dev`. On first successful login, `/auth/basic/login` persists an independent local username, `is_admin=true`, and a bcrypt hash (salt/cost included). Later logins use the database, including after bootstrap config removal. Local email-form usernames never merge with Google accounts; internal identities use URL-escaped usernames at `basic.localhost`. `/api/v1/me` exposes `is_admin`, `username`, and `has_password`, never hashes. Profile password changes require a session/current password and atomically revoke all user sessions; password-session creation checks the current hash transactionally to prevent stale-password races. GORM logs use parameterized queries to keep hashes out of logs. `pnpm -C web test` includes authentication client regressions.

- Inspection must bound rendering work in `internal/engine` before calling Starlark `String()`: truncating the repr afterward still allocates the entire value and can OOM-kill a capped child, especially under `-race`. Oversized/deep/opaque values are omitted; accepted reprs are still secret-redacted before the API response truncation. Keep `TestCgroupMemoryMax` exercising full inspection after its 64 MiB allocation.

- Artifact browser tests: `PLAYWRIGHT_CHANNEL=chrome pnpm -C web test:browser` uses local Chrome; omit `PLAYWRIGHT_CHANNEL` when Playwright Chromium is installed. The test command builds web assets and boots a disposable dev server/SQLite database. Do not build Go concurrently with Vite builds, which briefly empty the embedded `web/dist` directory.
- Requests that arm an instance Gate must retain `inst.requestMu` through audit draining; export also takes `Session.ExecMu` for an atomic VFS snapshot and `artifactMu` against teardown. Preserve failure audit batches across runtime transports. Artifact output is bounded, known-secret-redacted UTF-8 text; HTML belongs only on configured random-subdomain preview origins, never inline on the console origin. Interactive preview is opt-in, uses sandbox without `allow-same-origin`, and is not a strict network/CPU/memory sandbox.

- Scope every SDK `uv` invocation to `sdk/python/.venv`, including commands after `&&`; a command-prefix environment assignment does not apply to the following command. Do not inherit another project's global `UV_PROJECT_ENVIRONMENT`.

- Console interaction stability is a defined property: `docs/interaction-stability.md` (outcomes safety / continuity / predictability; invariants S spatial, C context, P predictability, F safety; mechanism and status per invariant; known gaps). UI changes must keep every invariant; cite IDs in tests/comments and update the status table when coverage changes. Enforced today: state styles are paint-only (S1, no transform/size/spacing/border width/font metrics/`content` on hover/press/focus/open/selected), menus never chase their trigger (S2), polled lists keep their shown order behind "Show N new" (`useHeldOrder`, S5), state/request-driven button labels use `SwapLabel` (S4), destructive actions use `Confirm` (F2), dropdowns/dialogs use the shared `ui.tsx` primitives and dialogs ask before discarding input (P2, C2). `web/src/interactionStability.test.ts` runs in `pnpm -C web lint` (and `test`); `e2e/workspaces.spec.ts` measures boxes frame by frame under hover and press.

- Artifact viewer: `/instances/:id/preview?path=...` renders outside the console shell but after App's authentication gate. File links open that console route with `noopener noreferrer`, never a bearer snapshot URL. Keep iframe pointer events disabled while the native JavaScript confirmation dialog is open; browser tests cover explicit consent, keyboard cancellation, and iframe teardown when switching to Source.

- HTML preview conversion uses the pinned esbuild Go API inside `Manager.Export`, under the instance execution/artifact locks and armed Gate. All dependency loads use the shared bounded artifact reader; esbuild must never fall back to host filesystem or network resolution. The public preview request remains path + mode; only internal worker export adds preview_mode/preview_html. Source and downloads are not rewritten. Browser tests cover data-URL scripts, classic globals, defer/async, local module/JSON imports, CSS imports, and sandbox isolation.
- Before esbuild bundling, normalize every JS module through its filesystem-free Transform API with non-literal import/require diagnostics promoted to errors. Dynamic glob imports bypass OnResolve in esbuild, so a VFS plugin alone is not an I/O boundary. Reject non-VFS OnLoad namespaces, use PlatformNeutral to avoid build-only environment substitutions, keep source maps disabled, and never set a filesystem ResolveDir for virtual modules.

- Application interrupts (EP-0016, `docs/proposals/0016-application-interrupts.md`): a run is a chain of independent steps (`main`, then handlers); `interrupt.wait` ends a step and the interrupt carries the full context — never resume inside a program or keep run state on workers. There is one interrupt kind (`interrupt.new(expires_in_s=None)` → `{id, resume_url, resume_token}`); handlers are not declared anywhere — `wait` resolves `handler`/`on_expire` against the program's top-level one-argument functions (not `main`, not `_`-prefixed), and the engine re-checks the entry after module init. The `interrupt` module (`internal/capability/interrupt`) is built by the engine for program sessions only and is never registered in a capability Registry (editor metadata documents it for completions). `interrupt.new` claims API-pre-reserved slots carried on `InvokeRequest.Interrupts` (4 per step, each with an `int_`-bound resume key), minted only when the release sources reference `interrupt` (`serving.UsesInterrupt`); there is no worker→API callback. The single resume route `POST /api/v1/interrupts/{id}/resume` (raw JSON object body) accepts the bound token (also early, while reserved) or any caller with Run; each interrupt resumes at most once (store CAS; later attempts `409 already_resolved`). Runs/interrupts live in `service/run` (dispatcher loop with `RunOnce` test hook, woken on resume; handler steps run on an ephemeral replica of the pinned release; a handler's return value is the run output); contexts/events/outputs are sealed with the vault cipher, and without `--secret-key` no slots are minted. `access.Checker` hides `int_`-bound keys everywhere except `InterruptToken` on the resume route. Console: Inbox (`/inbox`), Runs card, run page, Develop/Invoke `RunProgress`; inbox placeholders use `useHeldOrder(..., {keepGone: true})`. Browser tests that need interrupts start the runtime with a secret key (`startApplicationRuntime({ secretKey })`).

- LangChain example (`examples/langchain-agent/agent.py`): keep `use_responses_api=True` for OpenAI; `gpt-6-luna` rejects function tools with reasoning on Chat Completions. The installed `langchain-openai` supports Responses API routing without a dependency upgrade. Also keep `output_version="responses/v1"`: the default v0 format keeps only the last reasoning item per response, so multi-step tool turns fail with "function_call was provided without its required 'reasoning' item".

- Role boundaries: API-only implementations live under `cmd/calcside/internal` (API/auth/services, store implementation and migrations, catalog, routing, prompt, vault cipher, presentation). Worker configuration and API callback clients live under `cmd/calcside-worker`; top-level `internal` holds shared contracts and execution code. Never import command packages from shared code. `internal/node/architecture_test.go` enforces dependency boundaries. `subproc.ChildConfig.Extra` is opaque stdin-only JSON; the binary-specific `RunChild` configurator restores nonserializable dependencies such as the worker ext resolver.
